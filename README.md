# JMA Weather（Home Assistant カスタム統合）

> **個人用・無保証です。** 気象庁の Web サイトが使っている JSON（非公式の取得方法）を読みます。
> 気象庁がデータの形式や場所を予告なく変えると動かなくなります。Issue・Pull Request には対応しません。

気象庁の**府県天気予報**と**アメダス**の観測値から、Home Assistant の天気エンティティ（`weather.*`）を作ります。
数値予報モデルの値をそのまま使う天気 API と違い、天気と降水確率は気象庁が発表した予報そのものです。

| 項目 | 元のデータ | 取れないとき | 更新 |
|---|---|---|---|
| 現在の気温・湿度・風 | アメダス（選んだ地点、10分ごとの観測） | Open-Meteo の現在値 | 5分ごとに確認 |
| 現在の天気 | アメダスの降水量・日照から判定（下記） | Open-Meteo の現在値 | 5分ごと |
| 日ごとの天気・降水確率（今日から8日分） | 府県天気予報（3日分）＋週間天気予報 | Open-Meteo の日ごとの予報（10日分） | 30分ごと |
| 日ごとの最高・最低気温 | Open-Meteo（HA の自宅の地点）または気象庁の予想気温の地点（設定で選ぶ） | 気象庁の予想気温 | 30分ごと |
| 1時間ごとの予報（48時間） | 明日24時までの天気・気温・降水量は**天気分布予報の自宅のマス**、降水確率は府県天気予報の6時間ごとの値。湿度・風とそれより先は Open-Meteo | Open-Meteo | 15分ごとに発表を確認 |
| 今日・明日の最高・最低気温 | **天気分布予報の自宅のマス**の最高・最低（発表に含まれる日だけ） | 上の行の予想気温 | 同上 |

どの項目がどちらから来たかは属性で分かります（`observation_source`・`condition_source`・`daily_source`・`hourly_source`）。

外部ライブラリには依存しません（HA 同梱の aiohttp を使用）。API キーは不要です。

## 設定

設定 → デバイスとサービス → 統合を追加 → 「JMA Weather」

1. 府県（予報を出す気象台の区域）を選ぶ
2. 予報の地域（一次細分区域）、アメダスの地点、予想気温の元を選ぶ
   - アメダスの地点は、気温を観測している地点を HA の自宅から近い順に20か所出します（初期値は一番近い地点）
   - 予想気温は「Open-Meteo（自宅の地点）」が初期値です。気象庁の予想気温は府県の代表地点（例: 大阪府なら大阪）の値で、
     自宅と離れていると数度違うことがあるためです。Open-Meteo が取得できないときは気象庁の値を使います

アメダスの地点・予想気温の元は、あとから「設定」で変更できます。

## 天気分布予報（約5km四方のマス）

気象庁の天気分布予報の地図用データ（GeoJSON）から、HA の自宅の地点を含むマスの値を読みます。
府県天気予報は一次細分区域（県をいくつかに分けた広い地域）で1つですが、こちらは自宅のマスの値です。

- 3時間ごと、翌日24時まで。発表は1日3回（5・11・17時）。15分ごとに発表を確認し、新しい発表のときだけ取得します（1回約40ファイル）
- 天気は 晴れ・くもり・雨・雨か雪・雪 の5種類。晴れは 6〜18時を昼として `sunny`・`clear-night` に分けます（気象庁のページと同じ）。
  3時間で20mm 以上の雨は `pouring`
- 降水量は 1〜5mm などの区分なので、1時間ごとの予報には区分の中央の値を3で割ったものを入れます（1mm 未満は 0）
- 気温は3時間ごとの値を直線でつないで1時間ごとにします
- 時刻の決まり（実データで確認）: 天気・降水量は「その時刻までの3時間」、気温は「その時刻」の値

## 現在の天気の決め方

気象庁には「今この場所の天気」のデータが無いので、次の順で決めます（属性 `condition_source` に根拠が入ります）。

1. 直近30分にアメダスで降水があれば雨（`amedas_precipitation`）
   - 10分間に3.5mm 以上なら `pouring`。気温1℃以下なら `snowy`、今日の予報に雪があり3℃以下なら `snowy-rainy`、
     今日の予報に雷があれば `lightning-rainy`
   - アメダスの雨量計は0.5mm 単位なので、ごく弱い雨は「降水なし」になります
2. 昼（太陽の高度10度以上）で、地点に日照の観測があれば、直近30分の日照時間の割合で
   晴れ（70%以上）・晴れ時々くもり（20%以上）・くもり（`amedas_sunshine`）
3. 夜・朝夕・日照の無い地点は、天気分布予報の自宅のマスの今の3時間の天気（`jma_grid`）。
   無ければ今日の府県天気予報（`forecast`）。今は降っていないので雨・雪の予報はくもり、夜の晴れは `clear-night`

## 予報の天気の対応

気象庁の天気予報コード（100〜450）は、気象庁自身の分類（代表の天気: 晴れ・くもり・雨・雪）に従って変換します。

| 気象庁 | HA |
|---|---|
| 晴れの仲間（晴、晴後曇 など） | `sunny`、「曇」を含むものは `partlycloudy` |
| くもりの仲間（曇、曇時々晴 など） | `cloudy`、「晴」を含むものは `partlycloudy`、霧は `fog` |
| 雨の仲間（雨、**晴一時雨**、曇後雨 など） | `rainy`。雷を伴うものは `lightning-rainy`、雪・みぞれを含むものは `snowy-rainy`、大雨・暴風雨・一時強く降るは `pouring` |
| 雪の仲間 | `snowy`、雨・みぞれを含むものは `snowy-rainy` |

「晴一時雨」などは気象庁の分類で雨の仲間なので `rainy` になります。降水確率と合わせて見てください。

日ごとの降水確率は、6時間ごとの降水確率がある日（今日・明日）はその最大値、それ以降は週間予報の値です。
今日の値は、まだ終わっていない時間帯だけの最大値です。

## 属性

`problems`（いま取得できていないものの一覧。正常なら空）、`observation_time`（観測時刻）、`precipitation_10m`・`precipitation_1h`（降水量 mm）、`sunshine_10m`（日照 分）、
`forecast_report_time`（予報の発表時刻）、`forecast_area`、`today_weather`（今日の天気の文、例「くもり 昼過ぎ から 雨」）、
`condition_source`

## 取得に失敗したとき

- アメダスが取れない・欠測中（観測が2時間より古い）: 現在の気温・湿度・風・天気は Open-Meteo の値
- 気象庁の予報が取れない: 前回の予報を12時間まで使い、それより古ければ Open-Meteo の日ごとの予報
- 気象庁のデータの形式が変わって読めない（地域が見つからない、気温が1つも無い など）: 上と同じ扱いで、ログに「形式が変わった可能性」と出す
- どれも取れない: エンティティは使用不可になり、HA が再試行します
- 失敗はログに1回だけ WARNING を出し、回復したら INFO を出します。続いている問題は属性 `problems` に出ます
